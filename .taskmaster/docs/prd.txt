# Diplomacy CLI - Product Requirements Document

## Overview
Diplomacy CLI is a turn-based strategy game engine and interface inspired by the classic board game Diplomacy. The project serves as a proof of concept for exploring data-oriented design principles while building a complete, production-ready game system. The engine handles complex game mechanics including order validation, multi-pass resolution algorithms, convoy systems, and diplomatic negotiations.

The product targets strategy game enthusiasts, AI researchers, and developers interested in game engine architecture. It provides both human-playable interfaces and AI agent capabilities for autonomous gameplay and tournament simulation.

## Core Features

### 1. Complete Diplomacy Rules Engine (Go Backend)
- **What it does**: Implements the full Diplomacy adjudication system with DATC (Diplomacy Adjudicator Test Cases) compliance
- **Why it's important**: Ensures accurate, fair, and standardized game resolution that matches official Diplomacy rules
- **How it works**: Multi-pass resolution algorithm with syntax validation → semantic validation → conflict resolution pipeline

### 2. Order Validation Pipeline
- **What it does**: Parses and validates player orders through comprehensive syntax and semantic checking
- **Why it's important**: Prevents invalid moves and provides clear feedback to players about rule violations
- **How it works**: Lexer tokenizes raw orders → Parser creates structured orders → Semantic validator checks game state compliance

### 3. Multi-Pass Resolution Engine
- **What it does**: Resolves complex interactions between units including convoys, supports, and circular dependencies
- **Why it's important**: Handles the most complex Diplomacy scenarios accurately, including edge cases and paradoxes
- **How it works**: Hybrid architecture combining type-safe structs with performance-optimized arrays for iterative conflict resolution

### 4. AI Agent System
- **What it does**: Provides autonomous players capable of strategic gameplay and negotiations
- **Why it's important**: Enables single-player modes, AI tournaments, and strategy research
- **How it works**: Tactical AI (Go) for move calculation + LLM strategist (Python/DSpy) for diplomatic reasoning

### 5. Command-Line Interface
- **What it does**: Provides human-friendly game interaction through terminal interface
- **Why it's important**: Accessible gameplay without complex UI dependencies, ideal for developers and power users
- **How it works**: TUI (Bubble Tea) for interactive gameplay with map visualization and order input

### 6. HTTP API & Web Interface
- **What it does**: Enables web-based gameplay and external integrations
- **Why it's important**: Broader accessibility and potential for web frontends or mobile apps
- **How it works**: RESTful API with game state management, user authentication, and real-time updates

## User Experience

### User Personas
1. **Strategy Game Enthusiasts**: Players familiar with Diplomacy seeking digital implementation
2. **AI Researchers**: Developers building and testing diplomatic AI agents
3. **Game Developers**: Engineers studying game engine architecture and data-oriented design
4. **Tournament Organizers**: Users running competitive Diplomacy events

### Key User Flows
1. **Human Player Flow**: Register → Join/Create game → Submit orders → View results → Negotiate → Repeat
2. **AI Development Flow**: Configure AI agent → Run test games → Analyze performance → Iterate strategy
3. **Tournament Flow**: Create tournament → Configure participants → Run automated games → Generate reports

### UI/UX Considerations
- **Terminal-First Design**: Clean, readable text-based interface with ASCII map representation
- **Clear Error Messages**: Detailed feedback for invalid orders with suggestions for correction
- **Real-Time Updates**: Live game state updates during resolution phases
- **Accessibility**: Screen reader compatible, keyboard-only navigation

## Technical Architecture

### System Components
1. **Go Backend Engine**: Core game logic, validation, and resolution
2. **SQLite Database**: Game state persistence with ACID properties
3. **HTTP API Layer**: RESTful endpoints for game management
4. **Python AI Framework**: LLM-powered strategic reasoning
5. **TUI Frontend**: Bubble Tea-based terminal interface
6. **Web Frontend**: Optional browser-based interface

### Data Models
- **Game State**: Turn, phase, year, unit positions, supply centers
- **Orders**: Structured command objects with validation metadata
- **Players**: User accounts, AI agents, authentication tokens
- **Board**: Province definitions, adjacencies, coast relationships
- **Resolution Results**: Order outcomes, conflicts, dislodgements

### APIs and Integrations
- **Game Management**: Create/join games, submit orders, view state
- **User Authentication**: JWT-based session management
- **AI Integration**: Agent registration and automated play
- **Real-time Updates**: WebSocket connections for live gameplay

### Infrastructure Requirements
- **Development**: Nix-based environment for consistent tooling
- **Database**: SQLite for local development, PostgreSQL for production
- **Deployment**: Docker containers with health checks
- **Monitoring**: Structured logging and performance metrics

## Logical Dependency Chain

### Foundation First (Phase 1 → 2)
- **Core Engine** must be complete before persistence to ensure data model stability
- **Database Layer** provides foundation for all user-facing features
- **Authentication** enables secure multi-user gameplay

### Rapid Prototyping (Phase 3 → 4)
- **HTTP API** enables quick frontend development and testing
- **TUI Interface** provides immediate user feedback and validation
- **Parallel Development** of API and TUI using shared backend

### AI Integration (Phase 5)
- **Requires stable API** for agent communication
- **Builds on tournament infrastructure** from earlier phases
- **Can be developed independently** once API is stable

### Iterative Enhancement (Phase 6)
- **Web Frontend** leverages existing API without backend changes
- **Custom Variants** extend existing engine without breaking core functionality
- **Advanced AI** builds on basic agent framework

## Risks and Mitigations

### Technical Challenges
**Risk**: DATC compliance complexity with remaining 120 test cases
**Mitigation**: Incremental implementation with category-by-category validation, comprehensive test infrastructure already established

**Risk**: Performance bottlenecks in resolution engine
**Mitigation**: Hybrid architecture already optimized, profiling tools integrated, data-oriented design principles applied

**Risk**: AI integration complexity with LLM reasoning
**Mitigation**: Modular AI architecture, start with simple tactical AI, gradually add strategic reasoning

### MVP Scope Management
**Risk**: Feature creep delaying core functionality
**Mitigation**: Strict phase boundaries, each phase delivers working system, resist adding features until current phase complete

**Risk**: Over-engineering early phases
**Mitigation**: Focus on working software over perfect architecture, refactor as needed in later phases

### Resource Constraints
**Risk**: Single developer bandwidth limitations
**Mitigation**: Automated testing reduces manual validation, clear documentation enables future contributors, modular architecture allows parallel development

**Risk**: External dependency management (LLM APIs, hosting)
**Mitigation**: Local-first design with optional cloud features, fallback to simpler AI when external services unavailable
